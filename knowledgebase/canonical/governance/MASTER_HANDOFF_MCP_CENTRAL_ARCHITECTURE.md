## 1. Non-Negotiable Architectural Invariants

1. **Canonical Feature Definition (`CR-FEATURE-WORKFLOW-STANDARD-001`)**:
   - **Every Feature Is a Service Run by `>= 1` Bot**: Every feature, CLI command, MCP tool, or workflow is backed by a formal Service and owned by at least one registered Bot in `BotRegistry` (`src/hath0r_cli/step_runner.py`).
   - **Two-Level Topology on `AgentGraph`**:
     - **Level 1 (`HATH0R-MCP` — `Priority 1`)**: Central suite tools, declarative workflows, factories, and canonical knowledge reside on **`HATH0R-MCP`** (`http://127.0.0.1:38083` / `http://localhost:38000/mcp/`), indexed and governed by **`AgentGraph`**.
     - **Level 2 (`HATH0R-CLI` & Bot Memory)**: Operator CLI execution (`hath0r`) and Bot Memory (`.hath0r/memory/graph.json`, micro-sessions) reside at **Level 2**, synchronized with Level 1 via **`AgentGraph`** (`.hath0r/agentgraph/snapshot.json`).
   - **Workflow-First Standard ("Everything We Do Is a Workflow")**: Every task executes as a declarative workflow (`cfg/factories/*.yaml` or `mcp_workflow_*`). If a workflow does not exist for a task, ad-hoc execution halts and **offers to create and register the workflow first** (`hath0r workflow offer` / `mcp_workflow_scaffold`) using the original request as its acceptance test.
2. **4-Hour Automated Pre-Task Calibration (`max_age_hours = 4.0`)**:
   - Prior to starting any task, `ensure_calibrated(max_age_hours=4.0)` checks `.hath0r/cccd_state.json` (`ttl_hours: 4.0`) and automatically runs agent calibration when expired (`> 4.0` hours).
3. **4-Stage Iteration Cascade & `SuperSqueeze`**:
   - Strictly enforces `Stage 1: Task (Workflow-First + 4h Calibration + Cruise Control) → Stage 2: Hath0r-CLI (Level 2) ⇄ Hath0r-MCP (Level 1) on AgentGraph + SuperSqueeze → Stage 3: Computer → Stage 4: Web`.
4. **OpenFeature, OpenObserve (`OpenObservation`), OpenTelemetry (`OTel`) & `hath0r-net`**:
   - Exports OTel/OpenInference traces to **`Hath0r-phoenix`** (`http://localhost:38000/phoenix` / `http://Hath0r-phoenix:6006`), logs evals & calibration runs to **`Hathor-MLFLOW`** (`http://localhost:38000/mlflow/` / `http://Hathor-MLFLOW:5000`), and syncs work boundaries & settled facts with **`Hath0r-Cruise-Control`** (`http://localhost:38000/cruise/radar` / `http://Hath0r-Cruise-Control:8090`).
5. **Continuous, Non-Binary 4-Tier Task Evaluations (`CR-TASK-EVAL-001`)**:
   - Every ticket runs `pytest -q` and `hath0r evals run --task-id "issue-<N>"` + `hath0r evals verify`, producing a real continuous score (`0.80 <= R_task < 1.00`, never a hardcoded binary `1.0000`) via upgraded `TaskEvaluatorBot`, and returns the structured **Eval Scorecard Summary**.
